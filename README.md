# KG-ADMET Predictor integrated with PRING

This repository is the application/modeling layer around the PRING package.  It no longer reimplements PubChem extraction, CSV generation, Neo4j loading, EDA, or ML export logic.  Instead, the workflow is:

1. Use **PRING** to collect/process PubChem data and create a run folder.
2. Use this repository to load that existing run into **Neo4j**.
3. Train a baseline model from PRING's `graph/ml` exports.
4. Explore the graph, evidence, EDA outputs, and predictions in **Streamlit**.

The three original components are still present conceptually, but their responsibilities are clearer:

| Component | Responsibility now |
|---|---|
| `neo4j/` | Runs Neo4j and provides a `pring-loader` service that calls `python -m pring load-run` on an existing PRING run. |
| `modeling/` | Trains a reproducible tabular baseline directly from `graph/ml/*.csv` generated by PRING. It can export `PREDICTED_INTERACTION` relationships back to Neo4j. |
| `streamlit/` | Provides a PRING-schema-aware graph browser for compounds, proteins, evidence, external annotations, EDA outputs, and model predictions. |

## 1. Expected input from PRING

The app expects a PRING run folder similar to:

```text
runs/current/
  manifest.json
  graph/
    nodes/*.jsonl.gz or *.jsonl
    rels/*.jsonl.gz or *.jsonl
    csv/*.csv
    ml/
      compound_target_training_pairs.csv
      compound_target_link_prediction_pairs.csv
      candidate_missing_compound_target_pairs.csv
      node_features_compound_model_matrix.csv
      node_features_protein_model_matrix.csv
      edge_index.csv
      modeling_readiness_manifest.json
```

Create this run with the PRING package first, for example:

```bash
python -m pring build \
  --mode sparql \
  --scope expand-from-targets \
  --target-ids examples/inputs/target_ids_cyp450_5.txt \
  --taxid 9606 \
  --out-dir runs \
  --run-id current \
  --write-csv-mirrors true \
  --load-neo4j false \
  --candidate-pair-mode all \
  --activity-threshold-um 10 \
  --weak-activity-as-negative true
```

You can also reuse an existing run by copying or symlinking it to `./runs/current`.

## 2. Local Docker workflow

### 2.1 Prepare configuration

```bash
cp .env.example .env
```

Edit `.env` and set:

```dotenv
PRING_RUNS_DIR=./runs
PRING_RUN_DIR=/runs/current
PRING_PROJECT_DIR=./pring
PRING_PACKAGE_SPEC=https://github.com/asmaa-a-abdelwahab/PRING/archive/refs/heads/main.zip
```

`PRING_PROJECT_DIR` should point to a local PRING package clone if you have one, for example `A:/Repositories/PRING` on Windows. If that folder is missing or does not contain `pyproject.toml`, the containers install PRING from `PRING_PACKAGE_SPEC`. PRING is not published on PyPI, so do not set `PRING_PACKAGE_SPEC=pring`.

### 2.2 Start Neo4j and the app

```bash
docker compose up -d neo4j streamlit
```

Open:

```text
Neo4j Browser: http://localhost:7474
Streamlit app: http://localhost:8501
```

### 2.3 Load the PRING run into Neo4j

```bash
docker compose --profile load up --build pring-loader
```

The loader executes:

```bash
python -m pring load-run \
  --run-dir /runs/current \
  --neo4j-uri bolt://neo4j:7687 \
  --load-neo4j true \
  --rematerialize-schema true \
  --rematerialize-csv true \
  --candidate-pair-mode all \
  --activity-threshold-um 10
```

The load summary is written to:

```text
artifacts/reports/neo4j/load_summary.json
```

### 2.4 Train the model from PRING ML exports

```bash
docker compose --profile train up --build modeling
```

Outputs:

```text
artifacts/models/pring_tabular_baseline.joblib
artifacts/models/predictions.csv
artifacts/models/metrics.json
artifacts/reports/modeling/modeling_summary.md
```

If `MODEL_EXPORT_TO_NEO4J=true`, the modeling service writes prediction scores to Neo4j as:

```cypher
(:Compound)-[:PREDICTED_INTERACTION {score, predicted_label, model}]->(:Protein)
```

### 2.5 Generate EDA outputs

From your local Python environment where PRING is installed:

```bash
python -m pring eda --run-path ./runs/current --output-dir ./artifacts/reports/eda
```

The Streamlit app can also trigger this command from the **PRING run data / EDA** tab when PRING is available in the app container.

## 3. HPC workflow

Use the example Slurm scripts in `examples/hpc/`.

### Load an existing PRING run to Neo4j

```bash
sbatch \
  --export=ALL,PROJECT_DIR=$PWD,PRING_DIR=/path/to/pring,RUN_DIR=/path/to/pring/runs/current,NEO4J_URI=bolt://neo4j-host:7687 \
  examples/hpc/01_load_pring_run_to_neo4j.sbatch
```

### Train the model from `graph/ml` exports

```bash
sbatch \
  --export=ALL,PROJECT_DIR=$PWD,PRING_DIR=/path/to/pring,RUN_DIR=/path/to/pring/runs/current \
  examples/hpc/02_train_model_from_pring_run.sbatch
```

### Run EDA

```bash
sbatch \
  --export=ALL,PROJECT_DIR=$PWD,PRING_DIR=/path/to/pring,RUN_DIR=/path/to/pring/runs/current \
  examples/hpc/03_run_eda_from_pring_run.sbatch
```

## 4. What changed compared with the old implementation

- Removed the old Neo4j import path that expected manually prepared CSVs and old `Compound`/`Gene` property names.
- Neo4j loading now delegates to `python -m pring load-run`, so the implementation uses the same schema, constraints, JSONL graph artifacts, CSV mirrors, and ML exports created by PRING.
- The Streamlit app now queries PRING labels such as `Compound`, `Protein`, `Interaction`, `Endpoint`, `BioAssay`, `MeasureGrp`, `GO`, `Reactome`, `InterPro`, `ChEMBL`, and `BindingDB`.
- The modeling pipeline now reads PRING's `graph/ml/compound_target_*pairs.csv` and node feature matrices instead of exporting data from Neo4j with APOC.
- Predictions can be written back to Neo4j and displayed in the app.
- EDA is handled by PRING's native `python -m pring eda` command, keeping the analysis aligned with the run artifacts.

## 6. Troubleshooting

### `PRING_RUN_DIR does not exist`

Check that the host path in `PRING_RUNS_DIR` exists and that `PRING_RUN_DIR` points to the mounted container path, not the host path. Example:

```dotenv
PRING_RUNS_DIR=A:/Repositories/PRING/runs
PRING_RUN_DIR=/runs/cyp450_5enzymes_uncapped_raw
```

### `ERROR: Could not find a version that satisfies the requirement pring` or `ModuleNotFoundError: pring`

This means the container tried to install `pring` from PyPI. PRING is source-installed from your local clone or GitHub instead. Set one of the following:

```dotenv
PRING_PROJECT_DIR=/absolute/path/to/pring/package/root
```

or:

```dotenv
PRING_PACKAGE_SPEC=https://github.com/asmaa-a-abdelwahab/PRING/archive/refs/heads/main.zip
# or, with git installed in the image:
# PRING_PACKAGE_SPEC=git+https://github.com/asmaa-a-abdelwahab/PRING.git
```

### Model is not trained

Open `artifacts/models/metrics.json`. The most common cause is that the PRING run has too few supervised positive/negative labels. Re-run `pring load-run` or `pring build` with:

```bash
--candidate-pair-mode all \
--activity-threshold-um 10 \
--weak-activity-as-negative true
```

### Streamlit shows no compounds or targets

First load the PRING run into Neo4j:

```bash
docker compose --profile load up pring-loader
```

Then refresh the app.

## Neo4j startup troubleshooting

If `docker compose --profile load up --build pring-loader` stops with `container kg-admet-neo4j is unhealthy`, the PRING loader has not started yet. First inspect Neo4j:

```powershell
docker compose ps
docker logs kg-admet-neo4j --tail 200
```

For a fresh local database, the fastest reset is:

```powershell
docker compose down -v
docker compose up -d --build neo4j
docker compose --profile load up --build pring-loader
```

See `docs/TROUBLESHOOTING_NEO4J.md` for details.


### Neo4j plugin permission note

This project intentionally does not mount `/plugins` as a Docker volume. APOC is installed by the official Neo4j image from `NEO4J_PLUGINS`. If you see `Folder /plugins is not accessible for user: 7474`, run `docker compose down -v` and use the updated compose file.


### Neo4j Docker Desktop note

This project does not bind-mount `neo4j.conf` as a single file because Neo4j/APOC may update the config during startup. Single-file config mounts can cause `sed: cannot rename ... Device or resource busy` on Docker Desktop. The config is baked into the Neo4j image instead.


## Streamlit app mode

This package now uses the older CYP450-KG Streamlit interface while updating the Cypher queries for PRING Neo4j graphs. The sidebar actions are preserved, but the implementation now queries PRING labels/properties such as `Compound.cid`, `Compound.preferred_name`, `Protein.protein_id`, `Protein.cyp_symbol`, `Interaction`, `Endpoint`, `MeasureGrp`, `BioAssay`, `SIMILAR_TO`, `ASSERTS_CHEMICAL`, and `ASSERTS_TARGET`.
